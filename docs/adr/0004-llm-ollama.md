# ADR 0004. Локальная языковая модель

- **Статус:** принято
- **Дата:** 2026-10-26
- **Контекст:** P3, FR-7, FR-10, NFR-2, NFR-6, NFR-7

## Контекст

Нужен чат на русском, вызов навыков через tool calling и работа без облака.
Ограничения: CPU, 16 ГБ RAM, уже установленная Ollama, без повторной установки
и без `winget`. Модель должна отвечать 1–3 предложениями и укладываться в
несколько секунд.

## Рассмотренные варианты

| Вариант | Плюсы | Минусы |
|---|---|---|
| Ollama + qwen2.5:3b-instruct | уже установлена, OpenAI-совместимый API, tools, русский | ~2 ГБ, первый токен 1–3 с на CPU |
| llama-cpp-python | полный контроль, без сервиса | сборка под Windows, ручной чат-шаблон и tools |
| LM Studio | удобный GUI | отдельная установка, не гарантируется на стенде |
| Облачная LLM | лучшее качество | ключи, аккаунты, приватность, запрещено в MUST |

## Решение

Использовать **Ollama** через OpenAI-совместимый endpoint
`http://127.0.0.1:11434/v1`, модель `qwen2.5:3b-instruct` (Q4_K_M), ключ-заглушка
`ollama`. Провайдер `OllamaProvider` реализует `LLMProvider`: `health()`,
`models()`, `warmup()`, `chat()`, `chat_stream()`. `keep_alive=30m` удерживает
модель в памяти. Health-check кэшируется на 15 с; при недоступности — degraded.

## Последствия

- Полный офлайн после `ollama pull`; аккаунт и ключ не нужны.
- Модель занимает ~2.16 ГБ (по `/api/ps`), первый токен ~2.5 с, короткий ответ
  ~2.8 с на тестовой машине. Для длинных ответов включается стриминг.
- qwen2.5:3b поддерживает tools, но иногда путает аргументы; pydantic-валидация
  и откат на текст обязательны.
- Качество ниже облачных моделей; системный промт ограничивает ответ
  одним–двумя предложениями и запрещает markdown.
- Ollama не устанавливается проектом: пользователь скачивает её сам и выполняет
  `ollama pull`. Отсутствие CLI не мешает HTTP-интеграции.
- При смене модели в настройках провайдер использует новый `config.llm.model`
  без перезапуска; health-check подхватит изменение.
