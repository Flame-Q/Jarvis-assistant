# Требования к голосовому ассистенту «Джарвис»

Документ фиксирует функциональные и нефункциональные требования, приоритеты
(MoSCoW), сценарии использования и границы проекта. Версия 1.0 соответствует
реализации в каталоге `src/jarvis`.

## 1. Назначение и границы

«Джарвис» — настольный голосовой ассистент для персонального компьютера под
Windows 10/11. Он активируется голосом или горячей клавишей, распознаёт русскую
речь, выполняет команды управления ПК и ведёт диалог с локальной языковой моделью.
Обязательная функциональность работает без интернета, API-ключей и аккаунтов.

В границы проекта входят: голосовой ввод, синтез речи, набор навыков ПК,
интеграция с Ollama, хранение истории и заметок, системный трей и документация.
Вне границ: мобильные ОС, умный дом, клонирование голоса, облачные LLM,
сложная автоматизация внутри сторонних приложений (например, отправка сообщения
в конкретный канал Discord).

## 2. Стейкхолдеры

| Стейкхолдер | Интерес |
|---|---|
| Владелец проекта | Пользоваться ассистентом для управления ПК и локального чата |
| Пользователь ПК | Управлять компьютером голосом, не отвлекаясь на мышь и клавиатуру |
| Администратор демо-стенда | Убедиться, что всё работает офлайн и воспроизводимо |

## 3. Глоссарий

| Термин | Определение |
|---|---|
| Wake word | Ключевая фраза активации («хей, Джарвис») |
| STT | Speech-to-Text, распознавание речи |
| TTS | Text-to-Speech, синтез речи |
| VAD | Voice Activity Detection, детектор речи/тишины |
| Навык (skill) | Изолированный модуль, выполняющий одну команду |
| Слот | Параметр команды, извлечённый из текста (город, длительность, громкость) |
| FSM | Конечный автомат состояний ассистента |
| Degraded mode | Режим без LLM или без сети, когда доступны только команды |
| Tool calling | Вызов навыка языковой моделью через JSON-схему |

### Правила маршрутизации

1. Детерминированные правила: триггеры навыков, RapidFuzz (допуск опечаток),
   извлечение слотов регулярными выражениями. Работает офлайн, занимает миллисекунды.
2. Если правило не сработало и фраза похожа на команду (начинается с глагола
   действия), вызывается LLM с JSON-схемами навыков. Аргументы валидируются pydantic;
   при невалидном JSON — откат к текстовому ответу без исключений наружу.
3. Иначе — обычный чат с локальной моделью (стриминг, озвучка по предложениям).

### Подтверждение опасных действий

Навык может требовать подтверждения (`requires_confirmation` или
`needs_confirmation(args)`). Ассистент запоминает действие и спрашивает «да» или
«нет». Ответ «да/подтверждаю» выполняет действие, «нет/отмена/стоп» отменяет его,
любой другой ответ оставляет вопрос открытым. По умолчанию действие не выполняется.

## 5. Нефункциональные требования

| ID | Требование | Как проверяется |
|---|---|---|
| NFR-1 | Реакция на wake word ≤ 0.5 с | Замер по логу `Wake word detected`; модель 80 мс/окно |
| NFR-2 | От конца фразы до действия ≤ 2.5 с без LLM; первый токен LLM ≤ 3 с | Лог `Handled in ...`, `docs/testing.md` |
| NFR-3 | Ответ голосом 1–3 предложения; полный ответ LLM ≤ 8 с | Системный промт + стриминг + замеры |
| NFR-4 | Старт ≤ 20 с, простой ≤ 7 % CPU, ассистент ≤ 1.2 ГБ RAM, с Ollama ≤ 6 ГБ | Диспетчер задач, `psutil`, замеры |
| NFR-5 | Приватность: микрофон пишется только после активации (wake word/hotkey/кнопка), аудио не сохраняется | Код: запись начинается в `_record_utterance` или `_record_manual`; файлы не создаются |
| NFR-6 | Отказоустойчивость: Ollama/модель/сеть недоступны → голосовое сообщение, degraded, без падения | Тесты с FakeLLM, ручная проверка |
| NFR-7 | Полный офлайн: wake word, STT, TTS, команды, LLM-чат (погода и поиск — сетевые) | Демо с выключенным Wi-Fi |
| NFR-8 | Windows-специфика изолирована в `os_win/` и навыках-адаптерах; `core/` не импортирует Windows API | Архитектурный обзор, mypy/ruff |

## 6. Сценарии использования

### UC-1. Выполнить команду на компьютере

**Актор:** пользователь. **Предусловие:** ассистент запущен, микрофон доступен.
**Триггер:** пользователь нажимает кнопку «Говорить», `Ctrl+Alt+Space`,
произносит «Хей, Джарвис» или нажимает `Ctrl+Alt+J`.

**Основной поток:**
1. Ассистент фиксирует активацию и переходит в состояние LISTENING.
2. В режиме кнопки запись идёт до повторного нажатия; в режиме wake word/hotkey —
   до 800 мс тишины (не более 12 с). Для ручной записи действует аварийный лимит 60 с.
3. Распознаёт текст (faster-whisper) и переходит в ROUTING.
4. Правила выбирают навык и извлекают слоты.
5. Навык выполняется, результат озвучивается, состояние возвращается в IDLE.
6. Команда и результат пишутся в журнал SQLite.

**Альтернативный поток A1 (правило не сработало):** фраза похожа на команду —
LLM возвращает tool call; аргументы валидируются; навык выполняется.
**Альтернативный поток A2 (обычный вопрос):** LLM отвечает текстом, ответ
озвучивается по предложениям.

**Исключения:**
- E1: микрофон недоступен → голосовой режим отключается, работает текст.
- E2: речь не распознана → «Не расслышал, повторите пожалуйста», возврат в IDLE.
- E3: программа не найдена → предложение ближайших вариантов из индекса.
- E4: Ollama недоступна → «Локальная модель недоступна, команды работают».

**Постусловие:** состояние IDLE, действие выполнено или пользователь получил
понятное сообщение об ошибке; аудио не сохранено.

### UC-2. Диалог с локальной LLM

**Предусловие:** Ollama запущена, модель `qwen2.5:3b-instruct` скачана.
**Основной поток:** вопрос → маршрутизация → LLM-стриминг → озвучка по предложениям
→ запись реплик в историю (не более 12 в контексте).
**Исключения:** таймаут (60 с, один retry) → сообщение об ошибке; модель не скачана
→ подсказка `ollama pull ...`, degraded-режим; невалидный tool call → откат на текст.
**Постусловие:** ответ озвучен и сохранён, ассистент готов к следующей команде.

### UC-3. Поставить таймер или напоминание

Пользователь: «таймер на 5 минут» или «напомни через час позвонить маме».
Ассистент извлекает длительность и текст, создаёт `threading.Timer`, сохраняет запись
в SQLite и подтверждает голосом. По истечении времени озвучивает напоминание и
помечает запись как сработавшую. Исключение: длительность не распознана → просьба
повторить; максимум — сутки.

### UC-4. Опасное действие с подтверждением

Пользователь: «выключи компьютер». Ассистент не выполняет команду сразу, а
спрашивает: «Выключить компьютер? Скажите да или нет». При «да» вызывается
`shutdown /s /t 60`, при «нет/стоп» действие отменяется. Любой иной ответ оставляет
вопрос открытым. По умолчанию (молчание, закрытие) действие не выполняется.
Аналогично работает shell-навык.

## 7. Приоритизация MoSCoW

- **Must:** FR-1…FR-10, FR-16, NFR-1…NFR-8.
- **Should:** FR-11…FR-15, FR-17 (реализованы).
- **Could (не входит в P0–P6):** barge-in, потоковое распознавание, Silero TTS,
  RAG через `nomic-embed-text`, интеграция с календарём.
- **Won't:** мобильные ОС, умный дом, клонирование голоса, облачные LLM в
  обязательной части.
